**A. 近景是"同一台相机换构图"，不是切固定机位（FR-MOV-05）**

`CameraFocusState` 是纯计算：进度 0→1，时长 0.9s（构造时按 3s 上限截断，改配置也改不坏），
距离 3.6→2.25m、俯角 35→32°、FOV 60→42°，**都走同一条 smoothstep 曲线**，所以没有硬切感。
因为是同一台相机，镜头仍然跟着角色、仍然能被右键转动——这就是"非固定机位"。

机位摆哪一侧是现算的：吧台内侧通道只有 1.2m 宽，站到人正后方会顶进前柜、整屏都是后背
（第一版截图就是这个结果）。所以沿"人→工作点"的左右两侧各 SphereCast 一次，选没挡住的那侧；
跟随点再朝工作点前移 0.42m、抬高 0.16m，把台面推到画面中间、把人让到边上。

**B. 五原语对应五种控件，全部只发请求（NFR-05）**

| 原语 | 控件 | 落到领域层 |
| --- | --- | --- |
| click | 圆形主按钮，指针按下→抬起 | `Click(按下时长)` |
| hold | 同一个按钮按住不放 + 进度条 | `Hold(dt)` 攒、`Release()` 结算 |
| select | 一排选项按钮 | `Choose(选项)` |
| place | 一排热点按钮 | `Put(热点)` |
| wait | 不用操作，进度条自己走 | `Await(dt)` |

界面手里只有 `CraftSession`，没有 `DrinkMaker`、没有 `OrderBook`，也没有任何 setter：
每个动作都是一次请求，被拒绝（`NotCurrent`/`Blocked`/`Served`）就只是被拒绝。
测试里"当前是放置步时发 Choose"验证了状态一点没动（NFR-05）。

**C. 判偏只有红闪 + 闷响，没有文字评级（FR-EVAL-03）**

`DrinkMaker.StepFinished` 里 `Off` → 全屏红闪（0.45s 衰减）+ `ProceduralSfx.CraftThud()` 低频闷响，
然后出「重做 / 继续」两个按钮（对应 7.9.4 的两个选择）。
`CraftSession` 不向界面暴露 `DrinkQuality`，EditMode 用反射把这条钉住了。

**D. 一处数据修正：取杯是"放置"不是"点击"**

配方第一步"取杯放到萃取口下"原来是 `click`，但它本质是放置（FR-MAKE-03 里 place 的定义就是"放杯、上托盘"）。
改成 `place` + 两个热点（萃取口 / 台面），错误的就是放到台面上。步骤数、判定步数都没变（7 步 / 判 3），
06 的测试只是把"取杯"从 `Click()` 换成 `Put("萃取口")`。

**E. 输入层**

`PlayerIntent` 加 `Cancel`（PC Esc / 移动端返回）；`PlayerInputRouter.SetUiMode(bool)` 进界面时
不锁光标、不发世界交互、走路清零，但保留右键转视角（近景仍可看）。
`KeyboardMouseInputSource.UiMode` 与 `VirtualJoystickInputSource.PressCancel()` 一一对应，PC 与移动端同一套逻辑。

**踩到的坑**

1. 指针事件必须走 uGUI 的 `IPointerDownHandler/IPointerUpHandler`（鼠标与触屏同一条路），
   场景里没有 EventSystem，`ProjectSetup` 按需补一个。
2. `UiKit.TextButton` 建了 Text 却忘了赋值 → 按钮底色在、字是空的。截图里一眼看出来。
3. 进度条一开始用改 `anchorMax` 控制宽度，读到的是 0：截图时序问题——测试脚本在一次
   `yield` 里灌完进度，界面还没刷新就拍了。改成 `Image.fillAmount` 并**拍前等一帧**才稳定。
4. 判"按住够不够"的阈值不能写 0.99：0.99×2.5s = 2.475s < 2.5s，照样判偏。
   测试与截图都改成"顶到 1 才松手"。

### 手势表（屏幕空间识别，后果落在台面道具上）

| 步骤 | 手势 | 后果 |
|---|---|---|
| cup（取杯） | 把杯子拖到萃取口下 | 拖到台面 = 放错；拖到萃取口 = 对 |
| grind（磨豆） | **按住绕圈** | 转多少磨多少：**不转就一点都不出**；粉面随进度从碗底往上涨 |
| tamp（压粉） | **按住往下拖** | 压头跟着沉；**拖歪了粉饼就是斜的**；压到底还要停住 |

| move（上托盘） | 把杯子拖到托盘 | — |
| milk（打奶） | 把奶缸拖到蒸汽位并**保持** | 不在位就没有蒸汽声、奶面也不抖 |
| serve（出杯） | 把杯子拖到出杯位 | 自动收界面 |
| drizzle（淋糖浆） | 按住横向划一道 | 划够长度才算 |

`CraftView` 只发 `BeginPress / Tick / EndPress / PutAt / Choose / Tap` 给 `CraftSession`，

**时间喂入分工**：`Wait` 由 `CraftPanel.Update` 每帧 Tick；`Turn / Push / Hold` 由 `CraftView`

### 偏差只做缺陷（老板选的那条）

## 返工三（2026-11-07 晚，建模重做）

老板原话：「现在的建模太粗糙了，我完全看不出来你截图里这是什么东西」。
原因很直接：**所有道具都是 `GameObject.CreatePrimitive(Cylinder/Cube)`**——粉碗是个圆柱加个内嵌圆柱，
压粉器是两根圆柱，马克杯是一个圆柱，工作垫是一块方块。近景凑到 0.8m，屏幕上就是一堆灰塑料。

### 做法：一条二维轮廓绕 Y 轴转一圈

新增 `Scripts/Bar/PropMesh.cs`（车床 / 旋转体）：

- **轮廓约定**：点的 x = 半径、y = 高度，顺序「底心 → 底面往外 → 外壁往上 → 顶面往内 → 顶心」，
  这样朝外法线自然是轮廓切线的垂线 `(d.y, -d.x)`。
- **硬边**：把同一个点连写两遍。`OutwardNormal` 遇到相邻点重合就退化成单侧切线，
  折角处自动是硬边、曲面处自动平滑 —— 不需要第二套平滑组机制。
- **法线手算，不走 `RecalculateNormals`**：接缝处（θ=0/2π）顶点不共享，重算会在正面留一条竖缝。
- 另有两个补充件：`Tube()`（Catmull-Rom 平滑路径扫圆截面，做杯把手 / 壶把）、
  `Slab()`（俯视圆角矩形 + 上下倒角的扁板，做工作垫）。
- `EnsureOutward()` 兜底：逐面比较面法线与顶点法线，多数反向就整体翻绕序。

新增 `Scripts/Bar/CraftProps.cs`（各道具的轮廓）：

| 器物 | 轮廓特征 |
|---|---|
| 滤碗 | 锥形外壁（底窄口宽）+ 3mm 圆润卷边 + 直筒内腔 + 内底倒角。内腔和外壁**同一个钢材质** |
| 粉饼 | 比例化轮廓 + 顶面缓丘（中心高边缘低）+ Perlin 颗粒起伏，像一捧粉不是一块塑料 |
| 压粉器 | 倒角底盘 + 收腰杆 + **深色木质柱形把手**（和底盘拆成两个网格） |
| 马克杯 | 锥形杯身 + 杯口 3.5mm 瓷厚 + 内壁 + C 形把手（圆管） |
| 奶缸 | 鼓形壶身 + 收口 + 顶点变形拉出的单边壶嘴 + 环形把手 |
| 糖浆瓶 | 瓶身 + 肩 + 瓶颈 + 深色金属盖 |
| 工作垫 | 圆角板两层：深色包边 + 内嵌的面 |

尺寸按真实器具 **1.6 倍**（近景 0.8m，真实尺寸的碗壁在屏幕上不到一个像素），
但**比例关系保持真实**：杯 > 奶缸 > 压粉器 ≈ 滤碗。上一版杯比碗还小，本来就不可能认出来。
所有道具 **pivot 都在底面中心**，摆放直接用台面高度。

### 踩到的坑

1. **压粉器把手和主体网格完全重合**。主体的轮廓一直画到把手顶，knob 又用同一段轮廓 ——
   两个网格叠在一起 z-fighting，钢材质赢，木把手根本看不见。
   主体轮廓改成止于杆顶（y=0.062），把手单独一件从 0.0575 起。
2. **"粉面升高"在俯视里读不出来**。54° 俯视下 1cm 高度差只有七八个像素，
   磨了 59% 和磨满了看起来一样。改成**粉堆一边长高一边铺开**
   （`spread = Lerp(0.18, 1, powderLevel)`），一小撮 → 盖住半个碗底 → 铺满，眼睛一量就知道。
3. **倾斜的粉饼在俯视里还是个正圆**。压歪了只转角度，屏幕上什么变化都没有。
   现在**粉饼整体偏到碗的一边**（`k = |deg|/15 × 0.0075`），另一侧露出一弯亮钢碗底，一眼就是压歪了。
4. **压粉时出现了"托盘落点圈"**。tamp 也是 `Press` 模式，`UpdateRings` 原来只要不是 serve 就画托盘圈。
   改成只认 `move` / `serve`。
5. **截图拍不到压粉瞬间**。原来的 `bar_defect` 在抬手之后拍，压粉器已经退回座位了。
   新增 `bar_tamp.png`：压到底、还没抬手时拍。
6. **判偏截图比状态慢一帧**：`feedback=Deviation` 已经变了，画面还是上一张的提示。
