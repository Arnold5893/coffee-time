**A. 配方只写一份，两种驱动共用（FR-MAKE-02）**

```json
{ "id": "grind", "name": "磨豆", "primitive": "hold", "judged": true, "param": 2.5, "cost": 3.0 }
```

- `param` 按原语解释：`hold` 是按住达标秒数、`wait` 是等待秒数、`click` 是按下达标秒数（0 = 点一下）。
- `cost` 是**自动驱动**（老板）这一步花多久。手动完全不看 `cost`，自动完全不看 `param`——
  两边读的是同一份步骤序列，只是推进方式不同。
- 四款 SKU：经典拿铁 7 步（判定 3）、生椰拿铁 8 步（判定 4，加了"选奶"）、桂花拿铁 8 步（判定 4）、
  焦糖玛奇朵 9 步（判定 4，淋酱不判）。全在 6–9 步内（FR-MAKE-05），判定步符合 7.9.5 的拿铁线口径。

**B. 五种原语走同一个入口（FR-MAKE-03）**

`Hold/Release`、`Click(press)`、`Choose(option)`、`Put(target)`、`Await(dt)`。所有请求先过 `Guard()`：

| 情况 | 返回 | 是否记偏差 |
| --- | --- | --- |
| 原语和当前步不符 | `NotCurrent` | 否 |
| 门槛没开（gate 步骤没做完） | `Blocked` | **否**（FR-EVAL-04） |
| 待决定重做/继续 | `Invalid` | 否 |
| 已出杯 | `Served` | 否 |

门槛实例：萃取的液流没停，`move`（取杯）就是 `Blocked`；测试里断言 `ErrorSteps` 仍为 0。

**C. 判定与四档（FR-EVAL-01/02）**

- 只统计 `judged=true` 的步骤；校验期**拒绝**给等待步打判定（等待没有手感差异，不该算错）。
- 错误率 = 错误步数 ÷ 判定步数；缺任一必需步 → 非常差，且缺步**不计入**错误步。
- 四档按 7.9.6：`0` 好 / `≤0.5` 一般 / `<1` 差 / `=1` 非常差。测试把 4 步线
  （0/1/2/3/4 错 → 好/一般/一般/差/非常差）与 3 步线（0/1/2/3 → 好/一般/差/非常差）都钉死了。
- 阈值可按饮品覆盖（`fairMax`/`poorMax`），默认 0.5 / 1.0。

**D. 偏差之后（7.9.4）**

判偏不自动往下走，进 `PendingRetry`：`RetryStep()` 重做（把偏差抹掉，回到未做），
`Continue()` 带着偏差继续。老板的自动驱动永远不会进这个状态。

**E. 可跳过、可提前出杯（FR-MAKE-01）**

`SkipCurrent()` 跳步，`Serve()` 随时可出杯，没做的必需步算缺步 → 非常差。
出杯后再发操作一律 `Served`。
