# Spec: 竖切（vertical-slice）——进店到交付一杯拿铁

Status: ready-for-agent
日期：2026-11-06
依据：《咖啡店3D游戏_设计方案.md》v4、`docs/fsr.md` v2.0（§4.2）、`docs/srs.md` v0.1、wayfinder 地图 `asset-route` 全部决策

## Problem Statement

玩家（老板的朋友）推开咖啡店的门，应该能走完整条最小核心体验：进店、去吧台帮忙做一杯拿铁、被老板当场评价、把咖啡端给客人；与此同时，店里的另一名客人不靠玩家也能完成"点单→等餐→收货→饮用→离开"的完整闭环。这是整个游戏核心命题的最小可玩验证。

## Solution

一条端到端可玩竖切，六步链路：

1. 店门外点击门 → 开门（门铃音效占位）→ 走进店内 → 门自动关闭
2. 走到吧台，镜头切入原地近景
3. 帮工做一杯拿铁线饮品：手动驱动、含判定步骤与偏差即时反馈、可提前出杯
4. 老板空闲时当场按四档评价（模态对话）
5. 玩家自己端到客人座位交付，客人道谢
6. 并行地：一名客人走完闭环（进店 → 前台点单 → 老板自动制作 → 老板送餐 → 饮用 → 离开）

## User Stories

1. 作为玩家，我希望游戏开始后出现在店门外，以便获得"来到朋友的店"的开场感。
2. 作为玩家，我希望点击门后看到开门动作并听到门铃，以便进店有仪式感。
3. 作为玩家，我希望进店过程由我自己走完而不是过场动画，以便保持掌控感。
4. 作为玩家，我希望进店后没有任何引导或任务提示，以便自由探索。
5. 作为玩家，我希望用键盘（PC）/虚拟摇杆（Android）走路、鼠标/拖动旋转镜头，以便在店内移动观察。
6. 作为玩家，我希望镜头不能缩放，以便操作规则统一。
7. 作为玩家，我希望走到吧台附近时出现"帮老板做杯咖啡"的交互入口，以便开始帮工。
8. 作为玩家，我希望进入吧台操作后镜头变为原地近景、收紧视野，以便看清操作台。
9. 作为玩家，我希望挑单在对话里完成——老板问"你想做哪个？"并给出 2–4 个饮品选项，以便交互自然不界面化。
10. 作为玩家，我希望选定后锁定不可更换，以便每杯都有始有终。
11. 作为玩家，我希望做拿铁按步骤进行：取杯→磨豆→压粉→萃取→加奶→加风味→出杯，以便体验完整制作流程。
12. 作为玩家，我希望"按住"类步骤（磨豆、加奶）按住直到达标，有即时的声音/画面反馈，以便有手感。
13. 作为玩家，我希望萃取是自动等待过程、液流停了才能取杯，以便有节奏呼吸。
14. 作为玩家，我希望操作不到位时能通过音效和画面察觉到偏差，且没有文字评级，以便自己判断要不要重做该步。
15. 作为玩家，我希望可以跳过步骤提前出杯，以便按自己的节奏来。
16. 作为玩家，我希望老板空闲时在我出杯后当场评价（好/一般/差/非常差四档），差时必定指出问题，以便我知道做得如何。
17. 作为玩家，我希望做得非常差（含缺步）时可以选择重做或交给老板做，以便有出路而不是卡死。
18. 作为玩家，我希望评价对话是模态的、空格/点屏推进，以便节奏可控。
19. 作为玩家，我希望做完后自己端到客人座位交付，客人道谢，以便获得完成感。
20. 作为玩家，我希望端杯时走得比平时慢，以便有"小心端着"的感觉。
21. 作为玩家，我希望我没选的订单由老板真实地做（可见动画与计时），以便店是活的。
22. 作为玩家，我希望看到一名客人进店、点单、找座、等餐、收货、饮用、离开，以便店内空间有生活感。
23. 作为玩家，我希望客人点的单由老板自动制作并送达，不需要我参与，以便我可以只做自己的事。
24. 作为玩家，我希望全程不会死锁：任何中断后都有明确状态，以便体验稳定。

## Implementation Decisions

### 架构（遵循设计方案 §14.2）

- 组织方式：状态拥有者＋操作请求＋状态机＋领域事件。只有状态拥有者可改状态；状态变化发布领域事件供动画/音频/UI 订阅。
- 竖切涉及的状态机（设计方案 §14.3 子集）：进入流程、座位占用、订单、帮工会话、饮品制作、交付、对话、NPC 行为、老板行为。
- 配置化数据（设计方案 §14.5 子集）：座位（至少含竖切用的客人座位与吧台凳）、商品（拿铁线 4 款 SKU）、配方（拿铁线步骤序列与判定参数）、NPC（一名客人的最小配置）、老板（邀约/四档评价台词占位）。

### 模块划分

- **进入流程**：门外区域、门交互、开门/关门、门铃事件。
- **玩家控制**：走路、碰撞、交互入口检测、统一输入层（PC/Android 同一业务调用）。
- **镜头**：跟随镜头＋原地近景切换，无缩放。
- **做饮品系统**：配方数据＋手动驱动＋自动驱动共用一份；五种操作原语（按住/点击/选择/放置/等待）为 UI 级交互；判定与偏差记录；系统门槛（萃取未完不可取杯）。
- **评价系统**：错误率计算、四档阈值、老板空闲判定、模态评价对话。
- **交付系统**：谁做谁送、送达核对归属、交付事件。
- **老板系统**：自动制作队列、送餐、空闲玩电脑（占位动画即可）。
- **客人（NPC 最小版）**：一名客人的进店→点单→落座→等餐→饮用→离开。
- **座位系统**：占用/空闲状态，客人落座与释放。

### 资产与场景（来自 asset-route 地图决策）

- 场景：`coffee_shop.blend` → FBX（嵌纹理）→ Unity → Extract Textures → 转 URP；按 06 票结论把前柜北移 ~0.9m（通道 ≥1.2m），吧凳/Bar_Rack/吊灯随移。
- 角色：Quaternius Universal Base Characters（CC0），竖切用默认外观即可，不做角色创建界面。
- 动画：Mixamo 剪辑（走路/坐下/打字/idle）＋ Mecanim Humanoid retarget；吧台按住类动作用程序化 IK；端杯行走＝走路＋上半身 IK 遮罩。
- 纹理源文件：`仅供参考的文件/textures/`（已从 GLB 抢救）。
- 音频：全部用占位音效（门铃、磨豆、萃取、加奶、交付），占位不阻塞验收。

### 工程约定

- Unity 6000.3.28f1 + URP，工程放仓库内（Unity 标准 .gitignore）。
- 批处理/CI 调用 Unity 前必须 `export PROGRAMDATA='C:\ProgramData'`（本机环境坑，见 asset-route 01 票）。
- 首版平台 PC + Android；竖切验收含小米 14 真机。

## Testing Decisions

### 测试接缝（唯一接缝）

**领域层接缝**：操作请求进 → 状态与领域事件出。测试绕过渲染与输入，直接向状态拥有者发操作请求，断言状态机转换与事件序列。这是架构天然提供的最高接缝，UI/动画/音频在接缝之下不做单测。

### 什么是好测试

- 只测外部行为（状态、事件、配置驱动的规则结果），不测实现细节。
- 每条对应 SRS 的 FR 编号，可在验收追溯中回查。

### 测哪些模块（Unity Test Framework，Edit Mode）

- 订单状态机：合法/非法转换、送达点跟随客人当前座位。
- 饮品制作：拿铁线步骤序列、判定步计数、错误率计算、缺步→非常差、可提前出杯。
- 评价：四档阈值（4 步线：0 错=好、1–2 错=一般、3 错=差、4 错=非常差；缺步=非常差）、老板空闲/在忙两条通道的切换。
- 帮工会话：挑单锁定后不可更换；未选订单转老板。
- 交付：归属核对正确才能交付；端杯减速。
- 座位：占用/释放；客人不抢已占用座位。
- 进入流程：门的状态转换。

### 验收方式

SRS §6.1 竖切验收清单（FR-INIT-04/05/06、FR-MOV-01/02/05/06、FR-DLG、FR-ORD-01/02/03、FR-MAKE-01/02/03/04(拿铁线)/05/07、FR-EVAL-01～06/09、FR-SERV-01/03/05、FR-HELP-02/03/05/07、FR-BOSS-01、FR-NPC-02 单客、FR-MENU-01 拿铁线），PC 60 帧 + 小米 14 真机 30 帧（NFR-01），六步链路全程无死锁。

## Out of Scope

- 其余三条基底线（美式/无咖啡/茶线）与浸泡、搅拌工位。
- 天气系统、三时段推进、打烊流程。
- 角色创建界面、NPC 多轮对话与邀约闲聊、简单 NPC 群体。
- 正式美术与音效、性能分档细化。
- iPad。

## Further Notes

- 挑单选项在竖切中固定出现拿铁线饮品即可，2–4 个选项的积压逻辑属于完整版。
- 老板"首次邀约必定出现"的规则属于完整版；竖切用「帮老板做杯咖啡」常驻入口替代。
- 竖切通过验收后，本 spec 标记完成，进入阶段二全量制作系统的 spec。
